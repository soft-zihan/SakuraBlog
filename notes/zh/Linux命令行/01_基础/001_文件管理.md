# 📂 文件日常管理 (File Management)

这里涵盖了从查看、创建到移动、删除的所有基础文件操作。

## 0. 命令行的灵魂：Tab 补全

在继续之前，请记住这是提升效率的第一法则：**永远不要手动打全文件名**。

- 输入命令或文件名的前几个字母，按 **`Tab`** 键，系统会自动补全。
- 如果按一下没反应，说明有多个匹配项，连按两下 **`Tab`** 会列出所有候选项。

## 1. 浏览与查看 (View)

### pwd (Print Working Directory) - 我在哪？

- **`pwd`**：显示当前你所在的完整路径。当你迷失在多层文件夹中，它是你的"定位雷达"。
- **`pwd -P`**：显示物理路径（解析所有符号链接）。当你处于软链接目录中时，它会显示真实路径而非链接路径。
- **`pwd -L`**：显示逻辑路径（默认行为，保持符号链接）。

> 💡 **实战场景**: 在脚本中使用 `pwd` 获取当前工作目录：`SCRIPT_DIR="$(cd "$(dirname "$0")" && pwd)"`，这能确保无论从哪里执行脚本，都能获取到脚本所在的真实目录。

---

### ls (List) - 列出目录内容

- `ls -l`：列表显示详细信息 (权限/所有者/大小/时间)

  - **💡 详情解读**：
    `drwxr-xr-x  2  user  group  4.0K  Jan 1 12:00  my_folder`
    1. `d`：类型 (**d** 目录, **-** 文件, **l** 链接)。
    2. `rwxr-xr-x`：权限位。
    3. `2`：**链接数**。
       - 对文件：有多少个文件名指向它（硬链接数）。
       - 对目录：代表它包含的**子目录数量 + 2** (包含自身 `.` 和父目录 `..`)。因此一个空目录的显示数值是 **2**。
       - **举例**：如果你在 `test` 目录下新建一个子目录 `sub`，`test` 的链接数会从 2 变成 3，因为 `sub/..` 也指向了 `test`。
    4. `user`：文件**所有者**。
    5. `group`：文件**所属组**。
    6. `4.0K`：**目录项占用大小**。**注意**：这仅仅是该目录在磁盘索引中占用的空间，**不是**该目录下所有文件的总和。查看目录总大小请使用 `du -sh`；更系统的磁盘空间排查见进阶篇《磁盘与文件系统》。
    7. `Jan 1 12:00`：最后修改时间。
    8. `my_folder`：文件名。
- `ls -a`：显示所有文件 (包含以 `.` 开头的隐藏文件)

  - **💡 理解特殊符号**：
    - **`.`**：代表**当前目录**。
    - **`..`**：代表**上一级目录**。
- `ls -lh`：配合 `-h` 以人类可读格式 (KB/MB/GB) 显示大小。
- `ls -lt`：按修改时间排序（最新的在前），快速找到最近修改的文件。
- `ls -lS`：按文件大小排序（最大的在前），快速定位大文件。
- `ls -la`：组合使用，查看包括隐藏文件在内的所有文件的详细信息。
- `ls --color=auto`：启用彩色输出（多数系统默认开启），文件类型一目了然。
- `ls -F`：在文件名后添加类型标识（`/` 目录, `*` 可执行文件, `@` 符号链接）。
- `ls -1`：每行只显示一个文件，适合在脚本中处理输出。

> 💡 **Pro Tip**: 尝试使用 **`eza`** 替代 `ls` (需安装)，它支持 Git 状态显示、图标和树状视图：`eza -la --git`。

### stat - 查看元数据

- `stat file.txt`：显示文件的完整信息。
- **💡 核心概念：Inode (索引节点)**
  - Inode 是文件在磁盘上的"身份证号"，而文件名只是它的"别名"。
  - 一个 Inode 可以对应多个文件名（硬链接），但文件名必须通过 Inode 才能找到真实数据。
  - **查看 Inode 号**：`ls -li` 或 `stat file.txt | grep Inode`。
  - **实战意义**：当你删除文件时，实际是删除了目录中该文件名到 Inode 的映射。只有当所有指向该 Inode 的硬链接都被删除（硬链接数为 0），文件数据才会被真正释放。
- **stat 输出解读**：
  ```
  Access: 2024-01-01 12:00:00.000000000 +0800  # 最后一次访问时间 (atime)
  Modify: 2024-01-01 12:00:00.000000000 +0800  # 最后一次内容修改时间 (mtime)
  Change: 2024-01-01 12:00:00.000000000 +0800  # 最后一次元数据修改时间 (ctime)
  ```
  - **mtime**：文件内容被修改（如 `echo "new" >> file`）。
  - **ctime**：文件元数据被修改（如权限、所有者变化），**无法手动篡改**，常用于取证。
  - **atime**：文件被读取（如 `cat file`）。频繁更新 atime 会影响性能，现代系统通常使用 `relatime` 挂载选项优化。

### cd (Change Directory) - 切换目录

- `cd /path/to/dir`：切换到指定目录。
- **`cd`** (不带参数) 或 **`cd ~`**：快速返回家目录。
- `cd ..`：返回上一级目录。
- `cd .`：停在当前目录 (常用于运行当前目录下的脚本：`./script.sh`)。
- `cd -`：返回上一次所在的目录 (类似电视遥控器的"回看")。
- `cd /`：直接回到根目录。
- `cd ../..`：返回上两级目录（可继续叠加：`cd ../../..`）。

> 💡 **Pro Tip**: 尝试使用 **`z`** 或 **`zoxide`** 替代 `cd`，实现智能跳转 (如 `z pro` -> `/home/user/projects`)。它们会学习你的使用习惯，自动匹配最常访问的目录。

> 💡 **实战技巧**: 使用 `pushd` 和 `popd` 管理目录栈：
> - `pushd /tmp`：切换到 `/tmp` 并压入栈
> - `pushd /var/log`：再切换到 `/var/log` 并压入栈
> - `popd`：弹出栈顶，回到上一个目录
> - `dirs`：查看目录栈

## 2. 创建与管理 (Create & Manage)

### mkdir (Make Directory) - 创建目录

- `mkdir -p`：递归创建多级目录 (如 `mkdir -p a/b/c`)。
- `mkdir -v`：显示创建过程，适合在脚本中验证操作：`mkdir -pv project/{src,docs,tests}`。
- `mkdir -m 755`：创建时直接设置权限：`mkdir -m 700 private_dir`。
- **💡 批量创建**：使用花括号展开一次性创建多个目录：
  ```bash
  mkdir -p project/{src/{components,utils},docs,tests/{unit,integration}}
  ```
  这会创建一个完整的项目目录结构。

### touch - 创建空文件

- `touch file.txt`：创建一个空文件。
- `touch file1.txt file2.txt`：同时创建多个文件。
- **💡 核心功能**：`touch` 的本质是**更新文件时间戳**，而非单纯创建文件：
  - 如果文件不存在：创建空文件。
  - 如果文件已存在：更新其访问时间和修改时间为当前时间，**不会清空内容**。
- `touch -t 202401011200 file.txt`：设置指定时间戳（格式：YYYYMMDDhhmm）。
- `touch -c file.txt`：仅当文件已存在时才更新时间戳（不创建新文件）。
- `touch -r ref.txt target.txt`：将 target.txt 的时间戳设置为与 ref.txt 相同。

### cp (Copy) - 复制

- `cp -r`：递归复制整个目录。
- `cp -a`：**归档模式**。比 `-r` 更强，它会保留文件的所有属性 (权限、时间戳、链接关系)。
  - **实战场景**：当你需要迁移网站源码或备份配置文件时，**必须用 `-a`**。否则，所有备份文件的"修改时间"都会变成现在，导致你无法根据时间戳排障。
  - **等效参数**：`cp -a` ≈ `cp -dR --preserve=all`。
- **更安全的操作**：
  - `cp -i`：覆盖前**询问确认**（多数系统默认已设置别名）。
  - `cp -n`：**不覆盖**已存在的文件。
- `cp -u` (update)：仅当源文件较新或目标文件不存在时才复制。
- `cp -v`：显示复制过程，适合调试：`cp -rv src/ backup/`。
- `cp --backup`：覆盖前自动备份旧文件（添加 `~` 后缀）。
- **💡 批量复制**：`cp file{1,2,3}.txt /dest/` 会复制 file1.txt、file2.txt、file3.txt。

> 💡 **来自实战的补充**: 对于大文件或大量文件，**强烈推荐使用 `rsync` 替代 `cp`**：
> - **断点续传**：传输中断后可继续，而非从头开始。
> - **增量同步**：只传输变化的部分，速度更快。
> - **进度显示**：`rsync -av --progress src/ dest/` 实时显示进度。
> - **校验验证**：`rsync -ac` 通过校验和确保数据完整性。
> - **基本替代**：`cp -a src/ dest/` ≈ `rsync -a src/ dest/`（注意源目录末尾的 `/` 很关键！）

### mv (Move) - 移动与重命名

- `mv a.txt b.txt`：重命名文件。
- `mv file.txt /path/to/dir/`：移动文件到指定目录。
- `mv -i`：覆盖前询问确认。
- `mv -n`：不覆盖已存在的文件。
- `mv -v`：显示移动过程。
- `mv -u`：仅当源文件较新时才移动。
- **💡 批量重命名**：结合花括号展开 `mv file.{txt,md}` 将 file.txt 重命名为 file.md。
- **💡 实战技巧**：移动大量文件时，如果目标磁盘与源磁盘不同，`mv` 实际是"复制+删除"，此时用 `rsync` 更高效且可中断恢复。

> ⚠️ **避坑指南**：`mv` 在不同文件系统间移动目录时，会先递归复制再删除原目录，**不是原子操作**。如果中途失败，可能导致数据同时存在于两个位置。关键数据建议先用 `cp -a` 复制，确认无误后再 `rm` 删除源文件。

### ln (Link) - 链接

- `ln -s 源文件 软链接名`：创建**软链接** (类似 Windows 的快捷方式)。
- `ln 源文件 硬链接名`：创建**硬链接** (文件的另一个名字)。
- `ln -sf`：强制覆盖已存在的链接文件。
- `ln -sv`：显示创建过程。
- `readlink 链接名`：查看软链接指向的真实路径。

#### 💡 深度对比：软链接 vs 硬链接

| 特性                 | 软链接 (Symbolic Link) | 硬链接 (Hard Link)                      |
| :------------------- | :--------------------- | :-------------------------------------- |
| **本质**       | 一个指向路径的特殊文件 | 同一个 Inode 的不同别名                 |
| **跨文件系统** | 支持 (可跨分区/硬盘)   | **不支持** (必须在同一分区)       |
| **目录链接**   | 支持                   | **不支持**                        |
| **源文件删除** | 链接失效 (变成死链)    | **依然有效** (只要还有一个硬链接) |
| **Inode 编号** | 不同                   | **完全相同**                      |
| **文件大小**   | 等于路径字符串长度     | 与原文件一致                        |

- **避坑指南 1 - 软链接路径选择**：
  - **强烈建议使用绝对路径**：`ln -s /absolute/path/to/source link_name`
  - **为什么？**：如果你使用相对路径（如 `ln -s ./a.txt b.txt`），当你把 `b.txt` 移动到另一个文件夹时，它仍会尝试在"当前新位置"寻找 `./a.txt`，从而导致链接失效。
  - **例外场景**：如果你的链接文件永远不会被移动，且希望保持项目的可移植性（如 Git 仓库），可以使用相对路径。

- **避坑指南 2 - 软链接的"相对路径陷阱"**：
  ```bash
  # ❌ 错误示范（在 /home/user 目录下执行）
  ln -s ./projects/config.ini link.ini
  # 当你把 link.ini 移动到 /etc/ 时，它会寻找 /etc/./projects/config.ini（不存在！）
  
  # ✅ 正确做法
  ln -s /home/user/projects/config.ini /etc/link.ini
  # 或者使用相对于链接文件位置的路径
  ln -s ../home/user/projects/config.ini /etc/link.ini
  ```

- **💡 软链接实战场景**：
  1. **版本管理**：`ln -s /opt/app-v2.1 /opt/app-current`，升级时只需重新指向链接。
  2. **节省空间**：多个项目共享同一份大型依赖库，只需创建软链接。
  3. **跨分区访问**：在 `/home` 创建指向 `/data` 的链接，突破单分区容量限制。
  4. **配置集中化**：`ln -s ~/dotfiles/.vimrc ~/.vimrc`，用 Git 管理配置文件的经典做法。

- **💡 硬链接实战场景**：
  1. **增量备份**：`rsync --link-dest` 利用硬链接实现高效的增量备份（每个备份看起来都是完整副本，但相同文件只占用一份空间）。
  2. **防止误删**：重要文件创建硬链接作为"保险"，即使原文件被删除，数据仍可通过硬链接访问。
  3. **Docker 镜像**：Docker 利用硬链接实现镜像层的共享，节省磁盘空间。

- **💡 检查链接**：
  - 查看硬链接数：`ls -l file`（第 3 列数字）
  - 查找所有硬链接：`find / -samefile target_file 2>/dev/null`
  - 查找死链：`find . -type l ! -exec test -e {} \; -print`

### rm (Remove) - 删除 (⚠️ 极度慎用)

- `rm -i`：删除前**询问确认**。
- `rm -rf`：强制递归删除目录及其内容。
- `rm -v`：显示删除过程。
- `rm -- *.txt`：删除所有 txt 文件（`--` 防止文件名以 `-` 开头被误认为参数）。
- **⚠ 警告**：Linux **没有回收站**！`rm` 之后文件直接从磁盘索引中抹除，极难找回。
  - **极端情况下的数据恢复**：立即卸载文件系统 (`umount`)，使用 `photorec` 或 `testdisk` 工具尝试恢复，但成功率不保证。
- **`alias rm='trash'`**：**Pro 建议**：安装 `trash-cli` 并设置别名，将删除的文件移动到系统的回收站。
  - 安装：`sudo apt install trash-cli` 或 `sudo yum install trash-cli`
  - 使用：`trash file.txt` 代替 `rm file.txt`
  - 恢复：`trash-list` 查看，`trash-restore` 恢复

#### 💡 更安全的删除习惯（强烈建议养成）

1. **先预览后执行**：
   ```bash
   # ❌ 危险：直接删除
   rm *.log
   
   # ✅ 安全：先查看将要删除的文件
   ls *.log
   # 或者使用 echo 模拟
   echo rm *.log
   ```

2. **防止参数混淆**：
   ```bash
   # 文件名以 - 开头时的安全删除
   rm -- -dangerous-file.txt
   # 或者使用相对路径
   rm ./-dangerous-file.txt
   ```

3. **带空格/特殊字符的文件名**：始终用引号包裹：
   ```bash
   rm "my important file.txt"
   rm 'file-with-$pecial-chars.txt'
   ```

4. **交互式确认**：
   ```bash
   # 删除前逐个确认（适合少量文件）
   rm -i *.txt
   
   # 删除超过 3 个文件时提示一次
   rm -I *.txt
   ```

5. **💡 防护误删 rm -rf /**：
   - 现代系统通常有保护机制，但**不要依赖它**！
   - 永远在执行前**三思**：检查路径是否正确
   - 关键操作前**备份**：`cp -a /important /backup`
   - 使用 `--preserve-root` 参数（多数系统默认启用）

6. **💡 在脚本中的安全实践**：
   ```bash
   # 设置安全选项
   set -o errexit  # 遇到错误立即退出
   set -o nounset  # 使用未定义变量时报错
   
   # 删除前检查变量是否为空（防止 rm -rf / 灾难）
   if [ -n "$TARGET_DIR" ]; then
       rm -rf "$TARGET_DIR"
   fi
   ```

7. **💡 替代方案 - 使用 find 精准删除**：
   ```bash
   # 删除 7 天前的日志文件
   find /var/log -name "*.log" -mtime +7 -delete
   
   # 先预览（不加 -delete）
   find /var/log -name "*.log" -mtime +7
   ```

## 3. 统计与进阶技巧

### 排序与统计 (配合 ls)

- `ls -lhS`：按文件**大小**排序 (大文件在前)。
- `ls -lht`：按**修改时间**排序 (最近修改在前)。
- `ls -lhSr`：按文件大小**倒序** (小文件在前，`r` 表示 reverse)。
- `ls -R`：递归列出子目录下所有文件。
- **💡 组合使用**：找出最大的 10 个文件：
  ```bash
  find . -type f -exec du -h {} + | sort -rh | head -n 10
  ```

### wc (Word Count) - 文本统计

- `wc -l file.txt`：统计行数。
- `wc -w file.txt`：统计单词数。
- `wc -c file.txt`：统计字节数。
- `wc -m file.txt`：统计字符数（适合多字节字符如中文）。
- `ls | wc -l`：统计当前目录下有多少个文件。
- **💡 管道组合**：统计代码行数（排除空行和注释）：
  ```bash
  find . -name "*.py" -exec cat {} + | grep -v '^\s*$' | grep -v '^\s*#' | wc -l
  ```

### file - 识别文件类型

- `file my_script.sh`：显示文件类型 (如 "Bourne-Again shell script")。
- `file -i`：显示 MIME 类型：`file -i image.png` → `image/png`。
- `file -b`：不显示文件名，仅显示类型（适合脚本处理）。
- **💡 实战价值**：Linux **不依赖扩展名**判断文件类型，`file` 命令通过文件头部的"魔术数字"(magic number)识别。即使你把 `virus.exe` 改名为 `photo.jpg`，`file` 也能识破它。

### diff - 比较差异

- `diff file1.txt file2.txt`：逐行比较两个文件的不同之处。
- `diff -r dir1/ dir2/`：递归比较两个目录。
- `diff -u file1.txt file2.txt`：统一格式输出（适合生成 patch 文件）。
- `diff -y file1.txt file2.txt`：并排对比，差异一目了然。
- `diff -q`：仅报告文件是否不同，不显示具体差异。
- **💡 生成补丁**：`diff -u original.txt modified.txt > changes.patch`
- **💡 应用补丁**：`patch original.txt < changes.patch`

> 💡 **Pro Tip**: 尝试使用 **`delta`** 替代 `diff`，它提供极美观的语法高亮和 Git diff 查看体验。安装后配置：`git config core.pager delta`。
