# 🔍 查找与搜索 (Search & Find)

## 1. find & fd - 查找文件 (经典 vs 现代)
`find` 是跨平台的标准工具，功能极广；`fd` 是现代化的替代者，速度更快且语法更简洁（自动忽略 `.git` 和 `.gitignore`）。

- **基础搜索**：
  - `find . -name "*.log"` (经典) vs `fd log` (现代)
  - `find . -type f -size +100M`：查找大于 100M 的**文件**。
    - **尺寸单位**：`k`(KB), `M`(MB), `G`(GB), `c`(bytes)。`+`表示大于，`-`表示小于。
    - **坑点**：`-size 100M` 是"刚好100M"（极少匹配），必须用 `+100M` 或 `-100M`。
  - **按时间搜索 (`-mtime`)**：
    - `find . -mtime -1`：**24 小时之内**修改过的。
    - `find . -mtime +1`：**超过 24 小时** (2天前) 修改过的。
    - `find . -mtime 1`：**刚好**在 24~48 小时之间修改过的。
    - **时间参数族**：`-mtime`(修改时间), `-atime`(访问时间), `-ctime`(状态变更时间，含权限/所有者)。
    - **分钟级精度**：`-mmin +30` (30分钟前修改)，适合清理临时文件。
    - **参考文件比较**：`find . -newer reference.txt` (查找比 reference.txt 更新的文件)，支持 `-anewer`, `-cnewer`。
  - `fd -e jpg`：按后缀搜索 (fd 特有简洁语法)。

- **逻辑运算**：
  - **OR (或者)**：`find . -name "*.jpg" -o -name "*.png"`
    - **优先级陷阱**：`-o` 优先级低于 `-a`(与)，复杂条件需加括号：`find . \( -name "*.jpg" -o -name "*.png" \) -type f`
  - **NOT (排除)**：`find . -not -name "*.log"` 或 `find . ! -name "*.log"`
  - **AND (与)**：默认隐含，可显式写 `-a`，如 `find . -name "*.log" -a -type f`

- **排除目录 (性能优化关键)**：
  - **排除单个目录**：`find . -path ./node_modules -prune -o -name "*.js" -print`
    - **`-prune` 原理**：告诉 find 遇到该路径就"剪枝"，不再递归进去，大幅提升速度。
    - **⚠️ 坑点**：`-path` 后的路径**不能带末尾斜杠**（`./test` 对，`./test/` 错）。
    - **⚠️ 互斥**：`-prune` 不能与 `-depth` 或 `-delete` 同用，否则失效。
  - **排除多个目录**：`find . \( -path "./node_modules" -o -path "./dist" \) -prune -o -name "*.js" -print`
    - 注意 `\( \)` 前后有空格，防止 shell 转义。

- **进阶：查找并执行**：
  - `find . -name "*.tmp" -exec rm -f {} \;`
  - **语法拆解**：
    - **`{}`**：这是一个占位符，代表 `find` 找到的每一个文件名。
    - **`\;`**：表示 `-exec` 参数的结束。反斜杠是为了防止 Shell 把分号解析成命令分隔符。
  - **`find . -name "*.tmp" -delete`**：(更简洁) 直接删除找到的文件。
  - `fd -e tmp -x rm -f` (fd 的并行执行 `-x` 效率极高)
  - **交互式确认**：`find . -name "*.log" -ok rm -i {} \;` (每删除一个文件都会询问，适合敏感操作)。

- **💡 更多实战绝招**：
  - `find . -empty`：查找空文件或空目录。结合 `-type f` 或 `-type d` 可精确区分。
  - `find . -perm 777`：查找权限为 777 的危险文件。`-perm -777` 表示"至少包含这些权限"。
  - `find . -user root`：按所有者查找。`-group www-data` 按组查找。
  - **查找空文件 vs 0字节**：`find . -size 0` (仅0字节) vs `find . -empty` (空文件或空目录)。
  - **正则搜索**：`find . -regextype posix-extended -regex '.*\\.(log|txt)$'` (使用正则表达式查找 log 或 txt 文件)。
    - **正则类型**：`posix-extended`, `posix-basic`, `emacs`, `sed`，用 `-regextype` 指定。
    - **⚠️ 坑点**：`-regex` 匹配的是**完整路径**，不是文件名！所以模式必须以 `.*` 开头。
  - **格式化输出**：`find . -type f -printf "%T@ %p\n" | sort -n | tail -20` (按修改时间戳排序，列出最新20个文件)。
    - **printf 格式符**：`%f`(文件名), `%p`(完整路径), `%s`(大小/字节), `%u`(所有者), `%M`(权限), `%a`(访问时间), `%T`(修改时间)。

- **💡 专业建议：配合 `xargs` 使用**：
  - **为什么不用 -exec？**：`-exec` 像是一个强迫症：每找到一个文件，就启动一个新的进程去执行命令。如果你找到了 1 万个文件，系统就要启动 1 万个进程，开销巨大。
  - **`xargs` 的优势**：它像是一个高效搬运工：把 `find` 传来的 1 万个文件名打包，一次性传给 `rm` 命令，只启动一个或极少数进程，效率飞升。
  - **批量执行优化**：`find . -name "*.log" -exec rm -f {} +` (用 `+` 替代 `\;`，让 find 自动批量打包执行，兼具安全性和性能)。
  - `find . -name "*.log" | xargs rm -f`
  - **带空格的安全模式**：`find . -name "*.log" -print0 | xargs -0 rm -f` (防止文件名有空格或特殊字符导致命令误删)。
    - **原理**：`-print0` 用 null 字符(`\0`)分隔文件名，`xargs -0` 按 null 解析，彻底避免空格/换行符问题。
    - **最佳实践**：处理不确定文件名的场景，永远用 `-print0 | xargs -0` 组合。

- **⚡ 性能优化技巧**：
  - **限定搜索深度**：`find . -maxdepth 3 -name "*.log"` (只搜索3层目录，避免遍历整个文件系统)。
  - **先类型后名称**：`find . -type f -name "*.log"` 比 `find . -name "*.log" -type f` 快（先过滤类型减少后续匹配）。
  - **避免在 `/` 根目录搜索**：除非必要，用 `-xdev` 避免跨文件系统搜索：`find / -xdev -name "config.ini"`。
  - **fd 的性能优势**：`fd` 默认并行搜索 + 忽略 `.gitignore`，在代码仓库中比 `find` 快 5-10 倍。

## 2. locate - 全系统秒查 (基于数据库)
- `locate filename`：不扫描磁盘，直接查数据库，速度极快（比 find 快成百上千倍）。
- **工作原理**：Linux 系统通常每天会运行一个后台任务（cron job），把硬盘里的文件建个索引存进数据库（`/var/lib/mlocate/mlocate.db`）。
- **注意**：如果你刚创建了一个文件，`locate` 会搜不到（数据库未更新）。
- **手动更新**：执行 `sudo updatedb` 强制让系统现在就去扫描磁盘并更新索引。
- **locate vs find 对比**：
  | 特性 | locate | find |
  |------|--------|------|
  | **速度** | 极快（查数据库） | 较慢（实时遍历磁盘） |
  | **实时性** | ❌ 依赖数据库更新（通常每天一次） | ✅ 实时搜索 |
  | **功能** | 仅支持文件名模糊匹配 | 支持时间/大小/权限/类型等多维度筛选 |
  | **适用场景** | 快速定位已知文件路径 | 复杂条件搜索、定时任务清理文件 |
  - **最佳实践**：日常找文件先用 `locate`，找不到再 `sudo updatedb` 或换 `find`。
- **高级用法**：
  - `locate -i filename`：忽略大小写搜索。
  - `locate -n 20 filename`：只显示前 20 个结果。
  - `locate -r '\.log$'`：使用正则表达式（匹配以 `.log` 结尾的文件）。
  - **统计数量**：`locate -c filename` (只输出匹配的文件数量)。

## 3. grep / rg - 搜索文件**内容**
虽然 `grep` 属于文本处理，但它常用于"查找包含特定字符串的文件"。

- **常见场景**：
  - `grep -rn "API_KEY" .`：在当前目录下递归 (`-r`) 搜索包含 "API_KEY" 的行，并显示行号 (`-n`)。
  - **`grep -rl "API_KEY" .`**：只列出**文件名** (`-l`)。
  - **`grep -o "正则"`**：**只输出匹配的部分** (Only matching)。
    - *场景*：从一堆 HTML 中提取所有的 URL。
    - `grep -o 'http://[^"]*' file.html`
  - **统计匹配次数**：`grep -c "error" log.txt` (输出匹配行的数量)。
  - **反向匹配**：`grep -v "^#" config.txt` (排除以 `#` 开头的注释行)。

- **正则表达式实战**：
  - **基础正则 (BRE)**：`grep "error\|warning" log.txt` (`\|` 表示或，需转义)。
  - **扩展正则 (ERE)**：`grep -E "error|warning" log.txt` (`-E` 等价于 `egrep`，无需转义)。
  - **Perl 正则 (PCRE)**：`grep -P "\d{3}-\d{4}" phone.txt` (支持 `\d`, `\w`, `\s` 等高级特性)。
  - **实战建议**：默认用 `grep -E`，需要高级特性（如 `\d`, `\w`, 环视断言）时用 `grep -P`。
  - **常见正则模式**：
    - `grep -E "^[A-Z]" file` (以大写字母开头的行)
    - `grep -E "^[[:space:]]*$" file` (纯空白行)
    - `grep -oE "[0-9]{1,3}\.[0-9]{1,3}\.[0-9]{1,3}\.[0-9]{1,3}" file` (提取 IP 地址)

- **性能优化与参数对比**：
  - **`-F` 固定字符串**：`grep -F "literal_string" file` (不做正则解析，速度提升 2-3 倍)。
  - **`-w` 单词匹配**：`grep -w "cat" file` (只匹配完整单词 "cat"，不匹配 "category")。
  - **`--color=auto`**：高亮显示匹配部分（可写入 `~/.bashrc` 别名）。
  - **多文件搜索优化**：`grep -rn --include="*.js" "function" src/` (只搜索 `.js` 文件，跳过无关文件)。
  - **排除干扰文件**：`grep -rn --exclude-dir={node_modules,dist} "TODO" .`
  - **大文件搜索**：`grep --mmap -n "pattern" huge.log` (内存映射加速，但注意内存占用)。

- **现代化替代：`rg` (ripgrep)**：
  - `rg "keyword"`：速度比 grep 快几个量级（基于 Rust，支持 SIMD 并行），且默认忽略 `.gitignore` 里的干扰文件。
  - **rg vs grep 对比**：
    | 特性 | grep | ripgrep (rg) |
    |------|------|--------------|
    | **速度** | 快 | 极快（自动并行 + 智能跳过） |
    | **默认行为** | 搜索所有文件 | 自动忽略 `.gitignore` 和隐藏文件 |
    | **递归搜索** | 需加 `-r` | 默认递归 |
    | **正则支持** | BRE/ERE/PCRE | PCRE2 (更强大) |
    | **适用场景** | 通用文本搜索、脚本兼容 | 代码仓库搜索、日常开发 |
  - **rg 实战**：
    - `rg -t js "function"` (只搜索 JavaScript 文件)
    - `rg --files` (列出所有会被搜索的文件，用于调试)
    - `rg -g "!*.min.js" "map"` (排除压缩文件)

## 4. fzf - 模糊查找与交互
如果你记不清路径，`fzf` 是救星。
- `cd $(find . -type d | fzf)`：模糊搜索一个目录并跳转过去。
- `vim $(fzf)`：交互式搜索一个文件并用 Vim 打开。
- **fzf 核心优势**：模糊匹配算法（输入 `usrloc` 可匹配 `/usr/local/bin`），支持键盘上下选择、Ctrl+T 快速触发。
- **高级用法**：
  - `history | fzf`：模糊搜索历史命令并执行。
  - `ps -ef | fzf | awk '{print $2}' | xargs kill`：交互式选择并杀死进程。
  - **与 find 结合**：`find . -name "*.md" | fzf --preview "cat {}"` (实时预览文件内容)。
  - **多文件选择**：`vim $(fzf -m)` (按 Tab 多选，回车打开)。
- **安装**：`sudo apt install fzf` (Ubuntu) / `brew install fzf` (macOS)。

## 5. lsof - 这里的"查找"是侦探级的 (LiSt Open Files)
`lsof` 不只是查端口，它是 Linux 里的顶级侦探，用来回答："这个文件/资源到底被谁占用了？"

- **端口占用**：`lsof -i :8080` (谁占用了 8080 端口？)
  - **扩展**：`lsof -i TCP:8080` (仅 TCP), `lsof -i UDP:53` (仅 UDP)。
- **文件占用**：`lsof /var/log/nginx/access.log` (谁正在往这个日志写东西？)
- **目录占用**：`lsof +D /mnt/data` (我想卸载挂载点，谁还在占用这个目录里的文件？)
  - **性能警告**：`+D` 会递归遍历整个目录树，大目录很慢。用 `+d` 仅搜索单层。
- **进程追踪**：`lsof -p 1234` (PID 为 1234 的进程打开了哪些文件和库？)
- **按用户搜索**：`lsof -u www-data` (查看 www-data 用户打开的所有文件)。
- **排除用户**：`lsof -u ^root` (排除 root 用户)。
- **实战场景**：删除文件后磁盘空间未释放？用 `lsof | grep deleted` 找出仍占用已删除文件的进程，重启该进程即可。

## 6. which / type / whereis - 查找命令来源
- `which python`：查看 python 命令指向哪个路径（只在 `$PATH` 中搜索可执行文件）。
- **`whereis ls`**：查找二进制程序、源码和帮助手册的位置（搜索范围更广，包含 `/usr/share/man` 等）。
- `type -a ls`：查看 ls 是别名还是原始二进制文件。如果你发现命令行为怪异，用 `type` 检查是否被设置了奇怪的 `alias`。
- **命令查找优先级**：`alias` (别名) > `shell builtin` (内置命令) > `hash` (缓存) > `$PATH` (环境变量)。
- **最佳实践**：
  - 日常检查命令类型用 `type` (shell 内置，最快)。
  - 只看可执行文件路径用 `which`。
  - 找文档和源码用 `whereis`。
  - **调试命令来源**：`type -a python` 可显示所有匹配项（可能有多个 python 版本）。
