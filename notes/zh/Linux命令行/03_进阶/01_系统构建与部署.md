# 🏗️ 系统构建与部署实战

> **常见真实需求**：
> “会用 `apt install nginx` 只是开始。如果需要定制模块、排查启动失败、做成可维护的服务，你需要懂 `make`、安装布局与 `systemd`。”

本章节带你从源码编译开始，手动搭建一个生产级 Web 服务环境。

## 1. 从源码编译安装 Nginx

虽然包管理器（apt/yum）很方便，但源码编译能让你：
1.  使用官方源中没有的最新版本。
2.  **定制化**：添加第三方模块（如 `lua-nginx-module`）或裁剪不用的功能。
3.  深入理解软件的安装路径和依赖关系。

### 1.1 准备编译环境
在 Ubuntu/Debian 上，你需要安装编译器和核心依赖库：

```bash
sudo apt update
sudo apt install build-essential zlib1g zlib1g-dev libssl-dev libpcre2-dev ca-certificates
```
*   `build-essential`: 包含 gcc, make 等基础工具。
*   `libpcre2-dev`: Nginx 的 Rewrite/正则相关能力依赖（部分系统包名/版本可能不同）。
*   `zlib1g`: Gzip 压缩模块需要。
*   `libssl`: HTTPS/SSL 模块需要。
*   `ca-certificates`: 用于 HTTPS 下载时的证书链（避免 curl/wget 报证书问题）。

### 1.2 下载与解压
去 [Nginx 官网](https://nginx.org/en/download.html) 找最新 Stable 版本。

```bash
wget https://nginx.org/download/nginx-1.24.0.tar.gz
tar -zxvf nginx-1.24.0.tar.gz
cd nginx-1.24.0
```

### 1.3 校验下载包（避免“下到被替换的 tar.gz”）
生产环境建议至少做一次 sha256 校验：

```bash
sha256sum nginx-1.24.0.tar.gz
```

去官网把对应版本的校验值对上（校验值不一致就不要继续解压/编译）。

### 1.4 Configure (配置)
这是最关键的一步，决定了安装路径和启用的模块。

```bash
./configure \
    --prefix=/usr/local/nginx \
    --sbin-path=/usr/local/nginx/sbin/nginx \
    --conf-path=/usr/local/nginx/conf/nginx.conf \
    --pid-path=/usr/local/nginx/logs/nginx.pid \
    --error-log-path=/usr/local/nginx/logs/error.log \
    --http-log-path=/usr/local/nginx/logs/access.log \
    --with-http_ssl_module \
    --with-http_v2_module \
    --with-http_gzip_static_module
```
*   `--prefix`: 指定安装目录（推荐 `/usr/local/nginx`，方便统一管理）。
*   `--with-...`: 显式启用某些默认不开启的模块（如 SSL, HTTP/2）。
*   `--*-path`: 明确关键文件位置，避免“装完不知道配置/日志/PID 在哪”。

如果你后续要引入第三方模块，一般会用到：
* `--add-module=/path/to/module`（静态编进二进制）
* `--add-dynamic-module=/path/to/module`（编成动态模块，升级更灵活）

**检查输出**：如果报错 "Library not found"，说明缺少对应的 `-dev` 库，需回头安装。

### 1.5 Make & Install (编译与安装)

```bash
make -j4          # 使用 4 核 CPU 并行编译
sudo make install # 将编译好的二进制文件复制到 --prefix 目录
```

此时，Nginx 就安装在 `/usr/local/nginx` 下了。
验证：`/usr/local/nginx/sbin/nginx -V`

建议顺手把 `nginx -V` 输出保存下来（里面包含 configure arguments），以后升级/重编译能复现同一套编译选项。

## 2. 驯服 Systemd：将程序变成服务

手动运行 `/usr/local/nginx/sbin/nginx` 很麻烦，而且开机不会自启。我们需要把它交给 Linux 的管家 —— **Systemd**。

创建一个 Unit 文件：
`sudo vim /etc/systemd/system/nginx.service`

```ini
[Unit]
Description=The Nginx HTTP and reverse proxy server
After=network.target remote-fs.target nss-lookup.target

[Service]
Type=forking
PIDFile=/usr/local/nginx/logs/nginx.pid
# Nginx 启动命令 (绝对路径)
ExecStartPre=/usr/local/nginx/sbin/nginx -t -c /usr/local/nginx/conf/nginx.conf
ExecStart=/usr/local/nginx/sbin/nginx -c /usr/local/nginx/conf/nginx.conf
ExecReload=/usr/local/nginx/sbin/nginx -s reload -c /usr/local/nginx/conf/nginx.conf
ExecStop=/usr/local/nginx/sbin/nginx -s quit -c /usr/local/nginx/conf/nginx.conf
Restart=on-failure
RestartSec=2
LimitNOFILE=65535
PrivateTmp=true

[Install]
WantedBy=multi-user.target
```

**关键点解析**：
*   `[Unit]`: 描述服务依赖（在网络启动后再启动）。
*   `[Service]`:
    *   `Type=forking`: Nginx 启动后会 fork 出 worker 进程，主进程退出，这是标准的后台守护进程模式。
    *   `ExecStart`: 启动命令。
    *   `ExecReload`: 重载配置命令 (`systemctl reload nginx` 会执行这个)。
    *   `LimitNOFILE`: 提升文件描述符上限，避免高并发下出现 “too many open files”。
*   `[Install]`: `multi-user.target` 相当于以前的 Runlevel 3（多用户命令行模式），指定服务在什么运行级别下自启。

**启用服务**：
```bash
sudo systemctl daemon-reload    # 让 systemd 重新加载配置文件
sudo systemctl start nginx      # 启动
sudo systemctl enable nginx     # 开机自启
sudo systemctl status nginx     # 查看状态
```

快速验证两件事：
* 配置是否正确：`/usr/local/nginx/sbin/nginx -t -c /usr/local/nginx/conf/nginx.conf`
* 端口是否在监听：`ss -lntp | grep -E ':80|:443'`

## 3. 部署 Web 后端与反向代理

**场景**：你写了一个 Python (Flask) 或 Go 的后端服务，运行在 8000 端口。你需要通过 Nginx 把 80 端口的流量转发给它。

### 3.1 启动后端 (示例)
假设有一个 `app.py`：
```python
from flask import Flask
app = Flask(__name__)

@app.route('/')
def hello():
    return "Hello from Backend!"

if __name__ == '__main__':
    app.run(port=8000)
```
后台运行：`nohup python3 app.py &`

### 3.2 配置 Nginx 反向代理
编辑 `/usr/local/nginx/conf/nginx.conf`：

```nginx
server {
    listen       80;
    server_name  your_domain.com;  # 或者是 IP 地址

    location / {
        proxy_pass http://127.0.0.1:8000; # 转发给后端
        
        # 传递客户端真实 IP (面试常考点)
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;

        # 常见“跑起来了但很别扭”的细节：长连接与超时
        proxy_http_version 1.1;
        proxy_set_header Connection "";
        proxy_read_timeout 60s;
    }
}
```
**为什么要设置 Header？**
后端应用拿到的请求是 Nginx 发起的，所以 `Remote_Addr` 默认是 `127.0.0.1`。必须通过 `X-Real-IP` 告诉后端真实的客户端是谁。

重载配置：`sudo systemctl reload nginx`

## 4. HTTPS：配置 SSL 证书 (Certbot)

没有 HTTPS 的网站是不合格的。我们使用 **Let's Encrypt** 免费证书。

### 4.1 安装 Certbot
不同发行版的 certbot 安装方式差异很大：

* Debian/Ubuntu：通常可以先试 `apt`（版本可能偏旧）
* Ubuntu 新版本：更常见的是 `snap`（版本更新、更“官方”）

```bash
sudo apt install certbot
```

### 4.2 申请证书 (Webroot 模式)
Certbot 需要验证你拥有这个域名。它会在你的网站根目录下生成一个临时文件，然后通过 HTTP 访问来验证。

```bash
# 假设你的网站根目录在 /usr/local/nginx/html
sudo certbot certonly --webroot -w /usr/local/nginx/html -d your_domain.com
```

### 4.3 配置 Nginx 使用证书
修改 `nginx.conf`：

```nginx
server {
    listen 443 ssl http2;
    server_name your_domain.com;

    ssl_certificate /etc/letsencrypt/live/your_domain.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/your_domain.com/privkey.pem;

    # 推荐的安全参数
    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_ciphers HIGH:!aNULL:!MD5;

    location / {
        proxy_pass http://127.0.0.1:8000;
        # ... header 配置 ...
    }
}

# 强制跳转 HTTPS
server {
    listen 80;
    server_name your_domain.com;
    return 301 https://$host$request_uri;
}
```

### 4.4 自动续期
Let's Encrypt 证书只有 90 天有效期。
测试自动续期命令：`sudo certbot renew --dry-run`
在不少系统上，certbot 会自带 systemd timer；建议优先用它而不是手写 cron（更可观测、也更容易排查失败原因）。
